# Stochopia × OpenHyra P0 接口与数据契约草案

**状态**　2026-11-22，审阅修订稿。对应[世界模型研究 Harness PRD](Stochopia-OpenHyra-World-Model-PRD.md)。本文定义拟实施的接口、估计量和复验边界。第 5 节使用构造数据，作为可手算的验收样例。

## 0. 实施约定

- 契约沿用标准库 `frozen dataclass`、`validate()` 和 JSON 字典往返。共享定义放在 Stochopia 的 `stochopia/harness/contract.py`。OpenHyra 可导入该模块。Stochopia 的训练、模拟与评分侧独立于 OpenHyra 和 LLM。
- 现有函数的默认行为保持兼容。允许对 `evaluate_model` 增加可选的逐日原始量输出，复用现有轨迹和逐日汇总代码。旧指标和新读数共享计算路径。
- OpenHyra 任务的开发日志是选择和预测的权威记录。先保存事前记录，轮末追加结果。`DiscoveryLedger` 可保存已评估候选的发现记录，经验库和反馈包从同一任务记录投影。已评估候选列表无法代表各组实际选择的顺序。
- `runs/stochopia_tier0/<exp_id>/` 存开发材料。Verifier 接收单独配置的复验路径。实验号、轮号和任务键用于关联记录、预算记账和恢复进度。
- 方向、幅度与等效分别判定。整条定量预测获支持需要方向和幅度同时获支持。由评估方登记等效带、最小效应和预先指定的预测集合。

## 2. 数据契约

### 2.1 开发清单和冻结清单

| 记录 | 必需内容 |
|---|---|
| `ExperimentManifest`（开发视图） | `exp_id`、schema、环境配置、训练与开发数据引用、父模型和候选、诊断题、动作计划、对照组、共同预测候选、未选候选抽样规则、随机输入与预算、分析计划、拟合与测量版本。 |
| `FrozenManifest`（复验视图） | `exp_id`、`batch_id`、获准的测试数据与种子、冻结的分析计划、场景及评估任务清单。封存可供复算的选择、预测、搜索执行与费用记录、各组最终候选及停止理由，以及每项评估的父模和候选权重引用。 |

两份清单分别生成。开发视图可以登记计划中的测试范围，例如样本数和统计口径。实际测试日期、模拟命名空间、种子和原始数据定位由 Verifier 在开发运行前独立登记，仅在复验侧保存。开发入口在拟合前检查 train 与 dev 互斥。Verifier 在冻结时核对全部划分是否互斥，并校验任务是否来自已封存的开发记录。

- **数据划分。** 总实验明确登记 train、dev、test。训练只访问 train，开发测量只访问 dev。模拟日按生成家族、世界、命名空间和日索引定位，同时检查实际派生种子。真实日按规范化后的市场／标的／交易日标识检查互斥。同一原始数据换文件名或路径仍算同一来源。
- **拟合配置。** 记录训练重复 ID 和种子列表、初始化和抽样规则、训练预算、完整模型配置，以及价格和背景分支对应的权重引用。父模和候选使用匹配的训练计划。复验使用已冻结的拟合记录。
- **研究题和候选。** `ScenarioSpec` 声明稳定的 `scenario_id`、诊断题、环境、动作和时间窗。`CandidateRef` 声明 `candidate_id`、`backbone`、`recipe`、实现载荷和父模型。当前题的 `parent_id` 须指向明确的基线。每张候选菜单覆盖背景流与价格响应两类改动。题名和展示文本不得直接给出应选答案。
- **对照组。** `GroupSpec` 中 `evidence_llm`、`metrics_llm`、`no_llm` 各有一组。两个 LLM 组复用模型版本、基础指标、父模、候选菜单、共同预测集合、提示结构和可用计算预算。证据组额外看获准的开发证据。无 LLM 组预先登记排序或随机规则，使用相同的候选执行预算。
- **分析计划。** 按场景、读数和时间窗冻结单位、估计量、达标条件、最小效应、有限等效带、有效配对数、抽样方法、置信水平与种子。搜索和复验的预算分别登记。撮合场景记录引擎与版本。

### 2.2 事前选择、预测和试验费用

| 记录 | 字段与约束 |
|---|---|
| `SelectionRecord` | `selection_id`、实验／轮／组／场景、组内选择序号、父模、开发快照、候选菜单引用、选择动作及理由。动作包含选中候选、保留父模、主动弃权。弃权附原因。每轮本组看到候选结果前写入。 |
| `StructuredPrediction` | `prediction_id`、实验／轮／组／场景、解释、候选、父模、读数、单位、时间窗、方向、效应区间、适用条件、推翻条件及开发快照。引用冻结分析条目。近零预测使用该条目的等效带。弃权记录保留标识和原因。 |
| `SearchTrialRecord` | `trial_id`、关联 `selection_id`、实际运行的候选、序号、目的、已登记预算单位、实耗、完成状态和开发判定。区分主动选择的搜索试验与共同预测、抽测未选候选等核对任务。 |

选择可以携带多个预测。共同预测集或抽测候选的结果本身不构成某组的选择。额外核对结果如果提前进入组内决策，其消耗计入该组搜索预算。P0 的主要预测比较使用双方在同一预选候选和场景上、首次观察对应结果前提交的记录。后续更新保留轮次和原预测。

各组在第一轮共享基础快照标识，证据投影按组记录。后续开发反馈按组保留，避免一组的选择和结果替另一组完成搜索。核验拒绝补写结果已知的事前选择或预测。校验预测候选、父模、读数、时间窗和单位相容。方向区间须有限且与其方向一致。等效带由评估方提供，候选不能放宽。

### 2.3 拟合、逐日测量和报告

| 记录 | 字段与约束 |
|---|---|
| `FitRecord` | `fit_id`、候选和父模引用、配对训练重复 ID、训练数据与配置、种子、模型及价格／背景分支权重引用。 |
| `UnitObservation` | `unit_id`、`scenario_id`、训练重复 ID、候选、臂类型、对齐后的事件窗、指标原始量及单位。价格轨迹指标保存按日的原始响应和真值路径。可加指标保存足以按原口径汇总的分子、分母或逐日值。 |
| `PairedEvalResult` | `result_id`、`task_id`、数据划分、场景、候选和父模、拟合引用、动作及随机输入引用、臂与测量状态、逐日读数引用、效应估计、不确定性和费用。按 `unit_id` 对齐父子与真值。重复、缺失或错位须记录。完整配对之外的读数不进入默认估计。 |
| `PairedDelta` | 读数、估计量、单位、点估计、区间、有效配对数、方法、种子、置信水平、每个训练重复的点估计。不足以估计区间时记录原因。 |
| `PredictionVerdict` | `prediction_id`、对应测量、方向判定、幅度判定、等效判定、整条预测判定、区间宽度与理由。模型表现及得分变化单列。 |

臂类型沿用 `FREE`、`CLAMPED`、`TRUTH`、`VISIBLE`、`BLIND`、`NO_INJECTION`。测量协议声明可用臂及各自含义。`UNAVAILABLE` 表示读数欠缺或依赖未就绪。`INCONCLUSIVE` 表示有读数但不足以判定。`ABSTAINED` 表示主动弃权，进入覆盖率分母。报告分别列出这些状态的计数。

## 3. 执行、冻结和恢复

### 3.1 调用边界

| 入口 | 输入和行为 |
|---|---|
| `build_scenarios(manifest_view, split)` | 只接受当前阶段的清单及获准配置。生成确定的场景、日标识、动作和配对任务。 |
| `fit_candidate(train_plan, candidate_id, train_repeat_id, output_dir)` | 只接训练计划，返回 `FitRecord`。 |
| `run_paired_eval(eval_task, parent_fit, candidate_fit, output_dir)` | 同一个任务明确两侧拟合、场景和单位。父子使用相同的历史、注单计划和预先约定的共享随机输入。 |
| `run_dev_round(dev_root, round_index)` | 先保存选择和预测，再执行测量。整轮结果齐备后才发布开发反馈。 |
| `freeze(dev_export, verifier_config, verifier_root)` | 批次只建一次。校验训练、开发、测试互斥，封存候选与拟合引用、实际选择、搜索账、共同预测及复验任务。 |
| `run_verifier(verifier_root)`、`build_report(frozen_manifest, results)` | 只消费冻结件和获准的测试数据、只读权重。报告可用冻结清单与结果独立复算。 |

### 3.2 存储和访问范围

`runs/stochopia_tier0/<exp_id>/` 保存开发清单、每轮组内快照、事前选择和预测、任务账和轮末反馈。开发轨迹、模型工件和真实行情引用分开保管。真实行情留在库外。

独立配置的 Verifier 路径保存测试配置、冻结清单、已提交的任务结果和最终报告。允许读取清单中登记的权重与数据引用。开发配置、Context、Proposal 的检索范围和预算输入均不包含该路径或测试配置。入口按获准范围读写文件。若允许候选执行可任意读文件的代码，需要用进程权限或挂载范围隔离复验数据。兄弟目录命名只用于组织文件。

### 3.3 一次性复验

1. Verifier 对同一冻结批次取得排他执行权后才能开始。同一时刻最多一个进程执行该批次。在同一主机上可用进程持有的文件锁，异常退出时自动释放。
2. 每个评估任务用稳定的 `task_id` 在执行前登记。结果完整校验后原子提交到该任务的位置。故障恢复沿用同一冻结件和原随机计划。已提交的完整结果直接复用，未提交的任务继续或重试。
3. 全部任务达到终态后原子发布 `report.json`，报告本身作为完成凭据。已有完成报告时直接结束。技术失败只能恢复原批次，不能据此更换候选、场景或重抽种子。
4. 对照冻结批次和开发侧输入、检索与反馈记录验证不回流。冻结侧错误与预测反例留给人工审查。

## 4. 从逐日测量到判分

### 4.1 配对区间与估计量

对父模型和候选按日进行成组重采样，父模、候选和真值使用同一组日期索引。每次重采样按分析计划重算两边指标，输出候选减父模的差值。对于原口径就是逐日均值的标量，可以直接重抽逐日差值。对于曲线 RMSE，先在抽到的日期上求平均响应路径，再与同一批日期的平均真值路径算 RMSE。逐日 RMSE 的平均是另一项指标。执行峰值相对于真值的误差、回落比等也按各自冻结口径重算。 [现有路径汇总](../../experiments/tier0_feasibility.py#L311) · [配对 RMSE 实现](../../stochopia/harness/paired_stats.py)

多个训练重复时，每个重复保留配对点估计。若共享评价日，各次重采样对所有重复使用同一组日期，按冻结权重汇总每个重复的差值。报告区间反映给定这一批已训练模型时的日间测量不确定性，并另列种子间波动。训练重复不能当作新增独立交易日。单个配对日只报告点估计。配对日或训练重复数低于分析计划规定的下限时，保留可解释的点估计和覆盖率，判为证据不足。

### 4.2 预测和选择的判定

- **方向。** 用评估方冻结的最小效应口径给方向定义区域。以 $\varepsilon>0$ 为例，增加用 $[\varepsilon,+\infty)$，减少用 $(-\infty,-\varepsilon]$。区间完全落入所报区域为 `SUPPORTED`，完全不相交为 `REFUTED`，部分相交为 `INCONCLUSIVE`。
- **幅度。** 用同一条实测配对区间与事前效应区间比较，沿用完全落入、完全不相交、部分相交三种判法。方向、幅度各自记分。整条方向类预测只要一项被推翻就记 `REFUTED`，两项都支持才记 `SUPPORTED`。
- **近零。** 对照冻结等效带，以相同的三种区间关系判定。点估计接近零或区间包含零，均不足以支持等效。
- **选择。** 对 $Z\to X$ 用封存的选择记录与试验账，计首选达标率、首次开发达标的累计搜索费用、弃权率和相对共同已测菜单的效果差。首选和最终候选在冻结侧分别复核。搜索期未发现达标候选时，报告已用预算并标为未达标。$X\to\Delta Y$ 用两个 LLM 组共同的事前预测集合计方向、幅度、等效和覆盖率。模型改进分项同时保留，涨分但预测被推翻的记录可独立追溯。

## 5. 可手算的 Tier 0 样例

本例只用两个模拟日、两个测量时点和一组匹配的训练种子。数字是用于核对契约的构造读数。正式实验的重复数和最小样本量另在开发侧设定。以钳制价格曲线的 RMSE 为目标，定义模型分项为 $-\mathrm{RMSE}$。达标条件设为配对差值区间上界不高于 $-0.4$，其他模型护栏在本例中视为满足。一个主动搜索试验计 1 个预算单位，每组最多 2 个。共同预测核对与冻结测量单列。

### 5.1 开发侧事前记录

`base` 为父模型。`flow` 只改背景成交分支。`price` 只改价格通道，背景分支与 `base` 相同。两组 LLM 在看见任一候选结果前，对共同集合 `{flow, price}` 提交预测。以下列出与判分有关的记录。为便于追溯，三组第一轮的选择 ID 分别记为 `e-r1`、`m-r1`、`n-r1`，后两组第二轮记为 `m-r2`、`n-r2`。

| 组 | 第一轮事前选择 | 第二轮选择 | 事前预测，针对 `price` 相对 `base` 的停手末点钳制价格变化 | 冻结最终候选 |
|---|---|---|---|---|
| 证据组 | `price`，开发测量后达标 | 停止搜索 | 增加，$[0.5,1.5]$ tick | `price` |
| 指标组 | `flow`，开发测量后未达标 | `price`，开发测量后达标 | 减少，$[-1.5,-0.5]$ tick | `price` |
| 无 LLM 组 | 按登记次序选 `flow`，未达标 | `price`，开发测量后达标 | 不适用 | `price` |

两个 LLM 组对 `flow` 的同一读数都报近零，等效带为 $[-0.2,0.2]$ tick。方向项最小效应为 $0.2$ tick。表中的开发达标状态来自开发任务记录。锁定最终候选后，Verifier 收到事前预测、五条选择和相应费用。冻结任务 `test-flow`、`test-price` 分别把两个候选与 `base` 在下列测试日配对。`flow` 作为首选复核与共同预测任务，仍纳入冻结批次。

### 5.2 冻结侧逐日读数

下表每个二元组依次是**执行峰值、停手观察末点**的带符号钳制价格响应，单位为 tick。相同 `unit_id` 对齐父模、候选和模拟真值。

| 冻结模拟日 | 真值 | `base` | `flow` | `price` |
|---|---:|---:|---:|---:|
| A | $(4,2)$ | $(8,2)$ | $(8,2)$ | $(6,3)$ |
| B | $(6,3)$ | $(8,3)$ | $(8,3)$ | $(7,4)$ |
| 跨日均值 | $(5,2.5)$ | $(8,2.5)$ | $(8,2.5)$ | $(6.5,3.5)$ |

1. **模型分项。** `base` 和 `flow` 的平均路径相对真值的残差是 $(3,0)$，RMSE 为 $3/\sqrt{2}\approx2.1213$。`price` 的残差是 $(1.5,1)$，RMSE 为 $\sqrt{13/8}\approx1.2748$。`price` 的 $\Delta\mathrm{RMSE}\approx-0.8466$ tick，模型分项增加约 $0.8466$。
2. **配对重抽。** 手算枚举 AA、AB、BA、BB 四种有序抽样。每种共享日期索引，并重算平均路径 RMSE。`price` 相对 `base` 的差值依次约为 $-1.2473$、$-0.8466$、$-0.8466$、$-0.4142$ tick。对这四个数用线性插值取 2.5% 和 97.5% 分位，区间约为 $[-1.2172,-0.4466]$，其上界低于 $-0.4$。`flow` 与 `base` 每次的差值都是零。正式实验按冻结的重抽次数与种子运行。
3. **预测目标。** `price` 的停手末点逐日差值都是 $+1$ tick，配对区间为 $[1,1]$。`flow` 的对应差值和区间都是零。

### 5.3 冻结报告的预期输出

| 组 | 首选在冻结侧达标 | 首次开发达标的累计搜索预算 | 最终候选与模型分项变化 | `price` 停手末点预测判定 |
|---|---|---:|---|---|
| 证据组 | 是，`price` | 1 | `price`，$+0.8466$ | 方向支持、幅度支持，整条 `SUPPORTED` |
| 指标组 | 否，`flow` | 2 | `price`，$+0.8466$ | 方向推翻、幅度推翻，整条 `REFUTED` |
| 无 LLM 组 | 否，`flow` | 2 | `price`，$+0.8466$ | 不适用 |

两个 LLM 组关于 `flow` 的近零预测均为 `SUPPORTED`。无 LLM 组不进入预测覆盖率的分母。三个最终模型的成绩完全相同，选择记录仍能区分首选与搜索费用。指标组的最终选中记录 `m-r2` 和它在首轮提交的 `price` 预测都引用 `test-price` 的测量，由此分别得到**模型分项上涨**和**预测被推翻**。本样例的训练种子波动不可估。

评分边界可用同一个 $[1,1]$ tick 区间检查。若事前预测为增加 $[2,3]$ tick，方向为 `SUPPORTED`，幅度与整条预测为 `REFUTED`。这项检查独立于上表的搜索记录。

## 6. 验收用例

| 范围 | 首轮测试要检验的事实 |
|---|---|
| **F1 · 诊断题** | 用开发数据核对背景偏移主导与钳制残留主导的题能否分辨。信号不足时报告不可判定，保留依据。 |
| **F2 · 分组和划分** | 拒绝缺失或重复组别、LLM 版本或预算不匹配、候选或父模不匹配，以及训练、开发或测试单位重合。 |
| **F3 · 事前记录** | 校验共同候选的预测覆盖率、方向和区间。共同候选预测与实际选择分开。拒绝补写已见结果的事前预测。开发反馈按组投影。 |
| **F4 · 逐日测量** | 验证日标识对齐及错位、缺失处理。第 5 节的四种重抽能重算原曲线 RMSE。用反例区分曲线 RMSE 和逐日 RMSE 的均值。单日区间不可估。训练重复波动单列。同配置和随机计划重跑测量，在登记的数值容差内一致。 |
| **F5 · 冻结与复算** | 开发侧输入、快照和反馈不含测试配置与结果。冻结后改动开发记录不改变既有复验。并发启动只允许一个执行者。模拟中途失败后只恢复未提交任务。最终报告能从冻结清单和结果复算第 5 节两类结论。 |
| **接续性 · 主干、市场和轮次** | 同一入口切换 GRU 与对角 SSM 或 LRU，读取旧开发记录继续下一轮。实际 JAX-LOB 短用例核对成交、更新和导出对齐。缺依赖的降级测试和实际撮合测试分别运行，未运行的实际撮合标为未验证。 [盘口导出协议](LOB-Bench-IO-Protocol.md) |

实施时先固定第 5 节的报告口径，再用现有 Tier 0 离线入口跑模拟样本。具体阈值、训练重复数和 JAX-LOB 版本由 P0 实验清单登记。涉及测量、评分和数据划分的实现提交主会话审查。
