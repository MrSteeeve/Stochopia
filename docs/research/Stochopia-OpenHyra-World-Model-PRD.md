# Stochopia × OpenHyra 世界模型研究 Harness PRD

**状态**　2026-11-22，本文件用于工程实施和实验验收。完整实验及其研究问题见[端到端研究设计](Research-Design-EndToEnd.md)。首版按最终实验结构实现。Tier 0 提供第一批有真值的研究题，跨主干与短盘口用例验证接入路径。

## 目标

让研究者能够验证，OpenHyra 是否能根据对金融数据的认识，选择合适的世界模型改动，并在重训前预测它对外生母单响应的影响。交付物包括可执行的候选改动、事前预测、配对实验结果和适用条件。最终模型的冲击误差与智能体选择、预测改动的能力分别报告。

| 对象 | 定义 | 示例 |
|---|---|---|
| $Z$ | 关于数据中有哪些可学习信息、以什么形式出现的可检验判断。它可以支持一种对误差来源的解释。 | 自身子单和背景成交的方向持续性有区别，模型需要保留动作来源。开发侧证据是注单后背景同向成交增加，钳制后价格误差缩小。 |
| $X$ | 对指定父模型的一项可执行改动。明确修改输入、状态更新、读出、训练目标或生成协议中的哪一处。 | 保留价格分支，另用无注入路径提供背景成交方向。 |
| $Y$ | 给定历史和外生执行方案时的条件响应。Tier 0 看背景成交方向和价格。盘口阶段加补撤单、深度恢复和执行结果。 | 执行期的背景方向偏移、冲击峰值和停手后的价格路径。 |
| $\Delta Y$ | 改后模型与父模型在配对条件下的响应差。 | 事前预测背景方向偏移减小，钳制下的价格响应基本不变。 |

## 从最终实验结构开始写代码

所有阶段共用一条流程。研究者提交实验清单，OpenHyra 读取开发证据、登记候选和事前预测。Stochopia 按指定的市场环境构造配对场景，拟合候选并生成轨迹。对应的测量协议返回结果，OpenHyra 写入整轮开发反馈。Verifier 用同一执行和测量接口在独立路径完成冻结复验。

首版就支持同时指定**误差解释、模型主干、市场环境和评估协议**。四项独立配置。同一解释下可以比较多个主干，同一主干也能参与多个解释。首版用固定菜单和配额填充这些配置。后续替换提案与调度策略时，候选、反馈和复验沿用这一套流程。

| 边界 | 首版和后续共用的内容 | 由具体实验提供的内容 |
|---|---|---|
| **提案与记录** | 原有 `AlgorithmSpec`、`EvaluationResult` 和 `FeedbackPacket`。一项改动记录归属解释、父模型、事前预测、配对方案和验证结果。 | 固定菜单、开放式提案、不同岛的调度策略。 |
| **模型拟合与生成** | Stochopia 的任务入口接受模型规格、训练清单和生成请求，交回可按同一清单复评的模型与轨迹。 | GRU、对角 SSM、S5、Mamba 的实现与输入细节。成交和盘口模型可使用各自的内部张量格式。 |
| **市场场景与动作** | 每个场景明确初始历史、动作方案、时间尺度和计量单位。配对关系在执行前确定。 | Tier 0 用成交时钟和已知传播子真值。盘口用逐条消息、盘口初始状态与实际撮合。 |
| **测量与复验** | 共用配对执行和报告接口。结果指明对照组、读数、单位、观测区间和依据。Verifier 独立读取冻结清单。 | Tier 0 提供自由、钳制和模拟真值。盘口按协议提供可见、盲组或无单轨迹。实盘可提供独立估计的平均效应。 |

测量协议显式声明它能提供的对照和参考。钳制背景成交、盘口盲组和实盘均值使用各自的读数类型。缺少某项能力时，报告该读数不可用，保留其他可比读数。Tier 0 的模拟器、真值函数和评估可继续用于后续诊断和回归实验。

### 首版接续性验收

1. **换主干。** 同一 Tier 0 实验清单只切换主干配置，用现有 GRU 和对角 SSM 或 LRU 运行。两者共用候选、配对执行、报告和冻结复验流程。切换通过配置完成。
2. **换市场环境。** 同一入口跑通实际 JAX-LOB 驱动的短盘口用例。从几档已知深度和固定背景事件出发，配对运行有注单和无注单轨迹。断言注入子单按预定价格和数量成交，剩余盘口正确，每笔成交只扣减一次。固定所用 JAX-LOB 版本及入口，将消息张量、方向、时间和状态更新映射集中在撮合适配器。导出端按 LOB-Bench 协议写成逐笔消息和对应的**事件后**盘口，核对行对齐与订单引用。P2 扩大数据与场景规模时沿用该适配器和导出契约。JAX-LOB 依赖不可用时，盘口项标为未验证。 [JAX-LOB 官方实现](https://github.com/KangOxford/AlphaTrade) · [LOB-Bench 导出协议](LOB-Bench-IO-Protocol.md)
3. **接下一轮。** 第一次运行输出的开发侧候选、事前预测和反馈，可由同一入口加载，用于后续的候选选择或跨主干复验。追加新主干、新市场或新分项指标时，首版的配置和结果仍可读取和复跑。用开发记录或专用回归样例核验兼容性。

首版的共用执行与记录代码直接供 P1/P2 使用。S5/Mamba 及逐笔撮合各自的领域实现仍需增量开发。接续性以实际替换和续跑结果验收。

## P0 用户流程与验收要求

研究者创建一次实验，指定世界、父模型、候选菜单、注单条件、允许查询的开发证据与预算。OpenHyra 完成提案、执行和反馈，Verifier 在预先冻结的清单上做一次最终评估，输出两条映射的成绩与模型表现。

| 编号 | 功能 | 验收方式 |
|---|---|---|
| **F1 · 建立两类诊断题** | 题面都可出现冲击偏大或回落偏弱。A 类主要看背景流偏移，B 类看钳制后仍残留的价格误差。先用开发数据核对题目是否有可测的差异。 | 每题带父模型、动作条件、自由／钳制／真值路径及不确定性。若两类题的区别小于训练和模拟噪声，标为证据不足，暂缓因果能力结论。 |
| **F2 · 提交通用候选** | 同一题的各对照组收到相同父模型、基础指标、匿名的候选菜单。LLM 可以保留父模型。至少提供一项改背景流的候选和一项改价格响应的候选。 | 对照组共用动作、指标和成本口径。候选名称和提示不直接暴露哪项是该题预期答案。每个候选可对应多个解释。 |
| **F3 · 冻结事前预测** | 在本轮候选结果可见前，保存选择及给定候选的预测。每条预测包含比较基线、适用条件、读数、时间段、变化方向、等效或效应区间和推翻条件。 | 同一轮的候选读同一份开发快照。两个 LLM 组还须对同一批预先指定的候选提交预测，使预测成绩可直接比较。缺字段的提案先退回补齐。若证据不足，允许弃权并记录原因，计入覆盖率。 |
| **F4 · 配对测量** | 同一场景、初始历史、注单协议和随机数下比较父模型与候选。需要重训的候选使用匹配的数据、训练种子和预算。候选费用包含训练和评估。 | 可从保存的规格和 manifest 复跑。报告计分读数及按独立交易日／模拟日配对的差值区间。训练重跑的波动单独列出。 |
| **F5 · 反馈与一次性复验** | 每轮结束才写入开发反馈，保存成功、失败和无法判定的结果。Verifier 只对预先冻结的候选、对照和情景批次做一次评估。 | 检查测试解释、指标与轨迹均未进入 Context、Proposal、经验检索或下一轮预算决策。运行故障恢复时沿用同一冻结清单。报告能追溯每组的事前选择及预测，也能查到模型涨分但预测未获支持的记录。 |

### 第一轮的候选与对照

用现有 `plain`、`informed` 世界作为开发诊断的起点。两种世界的名字只用于调度。具体题面按测得的误差来源校准，必要时用模拟器参数构造匹配题。GRU 是首轮父模型。`separate_flow` 可作为背景流改动的起点。价格候选应能与**同一个背景流父版本**作配对，以便定位价格通道的变化。已有 `separate_flow_own_price` 组合了独立背景与自身标记价格分支，可作组合候选。候选目录同时保留父版本和未选中的有效改动。 [校准配方](https://github.com/MrSteeeve/OpenHyra/blob/world-model/tasks/stochopia_tier0/calibrate.py) · [模拟世界与注单真值](../../stochopia/sim/world.py#L89)

1. **带证据的 LLM**收到基础指标和事先约定的可辨识证据，例如自由路径与钳制路径的差异、钳制路径相对真值的残差。证据来自开发测量，提示不提供对应的应选改动。
2. **仅指标的同一 LLM**收到同样的基础指标、候选和预算。两组的提示结构、模型版本和可用计算预算匹配。
3. **无 LLM 搜索**在同一菜单内按预设随机顺序或固定规则选候选，使用相同的训练与评估预算。排序规则在运行前登记。

事前预测的评分包同时包含已选候选和按预先规则抽取的未选候选。候选选择的搜索预算与最终核对对照的评估预算分别报告，避免事后补测影响哪组先看到结果。

### 两条映射怎样计分

| 评估对象 | 主读数 | 如何解释 |
|---|---|---|
| **$Z\to X$** | 首选改动的达标率、发现首个达标候选所用的试验预算、相对共同已测菜单内最佳候选的效果差、弃权率。 | 即使各组最终选中同一模型，仍比较它们在看到评估结果前选了什么、用了多少预算。菜单最佳仅用于事后评估。 |
| **$X\to\Delta Y$** | 事前方向与实测方向是否一致、效应区间命中及其宽度、预计不变的指标是否落在预设等效带内。 | 两个 LLM 组用同一批候选的配对结果计分。检验等效时，配对差值区间须落在等效带内。证据不足以区分成立与不成立时，记为不可判定。 |
| **模型表现** | 下一事件负对数似然、自由与钳制曲线误差、执行期及停手后的方向偏移和价格响应。盘口另报 LOB-Impact 分项。 | 已按结构隔离的背景偏移只算实现核对，另用价格全路径及无注单读数检验效果。模型得分、事前预测判定各自保存。 |

**涨分与预测分别验收。** 候选总分提高时，若预期的响应变化未出现或方向相反，仍记录模型得分、原预测、配对实测和该预测的判定。预测未通过的记录进入开发侧反例。差值区间太宽的按不可判定记录。这两类结果都不能用总分覆盖。

在开发侧确定指标单位、效应最小量级、等效容差、配对比较方式和样本规模，再冻结。用多训练种子区分改动效果和训练噪声。Tier 0 的「自由减钳制」依赖其已知的背景不响应设定。若要声称某个网络通路承载了机制，再做针对该通路的遮蔽或替换实验。 [Tier 0 评估读数](../../experiments/tier0_feasibility.py#L287) · [大单冲击评分设计](LOB-Impact-Scoring-Design.md)

## P1 竞争解释与多主干

岛承载一个可被检验的误差解释。每岛保留支持证据、竞争解释、应满足的设计要求和有区分力的测量。GRU、对角 SSM、S5、Mamba 属于候选的主干属性。同一主干可参与多个岛，同一算子也可服务不同解释。每一条「解释与改动」的关联都要有单独的事前预测和对照。

| 竞争解释 | 设计要求 | 可先尝试的实现 |
|---|---|---|
| 自身子单被误读为背景成交延续 | 让模型看见自身动作在盘口上的后果，同时区分这笔动作与其他参与者的行为。 | 在两个主干上用同一动作输入或背景分支改法，先检验是否可迁移。自身标记须从获准信息生成。 |
| 盘口形成历史被编码丢弃 | 保留撤单和补单的顺序及间隔，并让补单和恢复预测读到它。 | 在实际 Mamba 上试由事件类型和间隔调节的慢状态，在实际 S5 上试多衰减尺度状态。先验证同一输入下的最小改动。该题使用逐笔盘口。 |

P1 保留两类对照。同一主干上比较只改编码／状态、只改读出和联合改动。同一改动意图在不同主干上实现后，用相同注单协议检验响应是否迁移。按预先分配的探索预算给每种解释机会。候选表现接近时，由 LLM 提出能区分它们的开发侧探测，再按预测分歧、噪声和成本安排执行。保留效果好的候选、未获支持的解释及各自的反例。 [AlphaEvolve 的种群调度参照](https://arxiv.org/html/2506.13131v1#S2.SS5) · [MDA 的分歧驱动实验设计](https://arxiv.org/html/2608.09696)

## 接口、交付物与边界

| 交付物 | 最少字段与读取方 |
|---|---|
| **实验 manifest** | 世界或数据来源、划分、时间窗口、模型和父版本、训练配置、动作计划、随机种子、预算和测量版本。盘口用例另记撮合版本。训练、执行和 Verifier 共用。 |
| **证据和提案记录** | 假设、证据引用及数据划分、失败解释、候选及父模型、修改位置、事前效应预测、近零预测、推翻条件、下一项探测。OpenHyra 按开发权限读取。 |
| **评估结果和报告** | 区分自由、钳制及配对真值，记录分项、按日汇总、种子、耗时和判定理由。最终报告给出世界模型表现、选择是否有效、预判是否命中和覆盖率。冻结侧结果供独立复验和最终审查。 |

- **职责边界。** OpenHyra 负责提案、取证与预算。Stochopia 执行模型规格，负责模拟、拟合、测量和评分。世界模型侧使用确定性的评估协议和预设随机输入。LLM 调用只在循环侧。候选可以读取获准的开发反馈并修改指定的模型部件。数据划分、撮合、测量和评分由评估方固定。
- **身份字段。** 参与者身份只用于复验。模型输入可以带已获准的自身标记。记录中也应区分观测到的动作来源和模型推断。
- **复现与数据。** 正式实验以冻结的 manifest 为准。模拟产物和真实数据产物分开存放，真实行情保存在库外。沿用现有格式和功能性标识。
- **P2 撮合。** 外生订单进入 P0 所用的 JAX-LOB 适配器，成交及盘口更新按公开协议进入可见组的模型输入，每笔成交只更新一次盘口。盲组撮合外生订单，同时用未注入路径驱动生成器。实盘比较同类订单的平均响应，校准行情条件、规模、时长和参与率。若真实侧缺少可识别的动作变化，结论限定在可观测对照或文献参照。 [原论文注单协议](https://arxiv.org/html/2610.27100v1#S2.SS1)

## 发布检查与待定事项

**第一轮从现有 Tier 0 离线入口开始。** 先用固定菜单跑父模型、背景流改动和价格响应对照，在开发侧核对两个诊断题的信号与配对读数。接着用同一入口登记事前预测、完成三组对照，并生成下一轮可读的开发记录。JAX-LOB 短用例通过同一入口做接续性检查。若依赖未就绪，照实保留该项未验证状态。

P0 发布前核对离线流程、三个对照、接续性检查及独立复验。每种情景至少要有一组可区分的已知故障与有效对照，或给出信号不足的诊断。冻结清单能复算选择与预测两类成绩，报告明确区分通过、未通过、不可判定和弃权。模型分项与预算一起发布，便于复核差异是否来自证据。

实施前用开发数据确定候选菜单、重复种子数和检验力。实际 S5/Mamba 的选型与算力、可用于实盘复验的外部干预记录仍待确认。
