**Step 4.1c 定稿**。64 个训练日、32 个开发日、LR 0.001、200 步的纯 GRU 配置通过独立复跑。复跑中 A 的 `x01` 自由路径 RMSE 差为 −6.066 tick [−6.393, −5.772]，B 的 `x12` 钳制路径 RMSE 差为 −2.438 tick [−2.728, −2.131]。两题诊断均为 5/5 预期分类。定稿参数和完整读数见 Step 4.1c 的表 2 和表 3。

**Step 4.1 历史筛选（2026-11-24，北京时间）**。增强信息漂移的配置在开发集上区分了两个诊断题。A 的背景流隔离使自由路径 RMSE 减少 6.593 tick，95% 区间为 [−6.958, −6.251]。B 在共用独立背景权重时加入自身标记价格分支，钳制路径 RMSE 减少 1.775 tick，95% 区间为 [−1.900, −1.643]。独立模拟日复跑确认了两项总体改善，B 有一个训练种子反向。建议沿用增强配置，正式阈值经人工确认后再登记。

## 数据、模型与配对口径

使用 Stochopia `d0f09c3`、OpenHyra `b3f252c` 的冻结实现。校准只拟合模拟 `train`，在模拟 `dev` 生成诊断与候选结果。三个配置共享 GRU 训练方案和五个独立初始化种子 `103, 137, 211, 293, 367`。每个配置 16 个训练日、32 个开发日、每种子 120 步。CPU 单线程、隐藏维度 32、1 层、batch 16、窗口 64、学习率 0.003，`own_start=inside`、标记无漏报或误报。背景权重对照额外拟合一个匿名对角 SSM，所有候选的价格主干均为 GRU。

| 开发配置 | train/dev 命名空间前缀 | B 题及共同训练世界 `info_drift` | `informed_frac` | 用途 |
|---|---|---:|---:|---|
| 标准 | `p0-step41-calibration-v1` | 0.85 | 0.40 | 复测脚本的默认世界 |
| 增强 | `p0-step41-calibration-v1` | 1.80 | 0.25 | 用同一日种子比较世界设置，下表主结果 |
| 增强复跑 | `p0-step41-replication-v1` | 1.80 | 0.25 | 用另一个 train/dev 命名空间重训和复测，保留五个初始化种子 |

A 的评估世界是 `plain`，`info_drift=0`、`informed_frac=0`。B 是 `informed`。两题共用各自配置登记的 informed 训练世界。其余共同参数为每模拟日 2,048 笔、预热 256 笔、`noise_std=0.50`、成交流 `n_slots=2, alpha=1.24, max_len=2048`、传播子 `beta=0.28, tau_max=96, n_scales=6`，其余字段沿用冻结代码默认。每个模拟日评估 6 个固定起点，上下文 48 笔。买卖两侧分别注入 12 笔，自身子单在合并时钟上间隔 3 个事件，`spacing=2`、`relax=18`。全路径 54 个合并事件。停手后的背景偏移从最后一个子单之后算起，共 20 个背景事件。

同一题内，候选与父模型共享交易日、训练种子、注入计划和逐日抽样输入。读数是候选减父模型。标量先取日均再等权汇总训练种子。RMSE 先对日路径按时间点平均，再对平均路径和真值做 RMSE，最后等权汇总各训练种子的 RMSE 差。95% 区间用 2,000 次成组日重抽，单次重抽的日期同时用于两个模型、真值和全部训练种子。区间以已训练模型为条件，训练噪声用五个种子的点估计范围另报。A/B 共用日种子，两个题的天数不相加。下一事件 NLL 使用归一化收益和无注入事件。冻结实现省略了高斯归一化常数，配对差值中该常数会抵消。

## Step 4.1 当时的参数建议

建议 `train / dev / test = 16 / 32 / 64` 个模拟日、`K=5`、每训练 120 步、每模拟日 6 个窗口、2,000 次日重抽。根据下表的开发集精度，64 天可作为正式复验的精度余量，实际检验力尚未测量。现有 `AnalysisSpec` 在开发和冻结侧共用，建议登记 `min_pairs=32, min_train_repeats=5`，正式测试清单另登记 64 个计划日并报告完成数。开发与正式复验使用独立的模拟日命名空间。训练和模拟日使用分开的种子流。

120 步还保留了先前开发预校准的有效设置。旧增强预校准（`p0-stronger-2026-11-23`，20 个开发日、同样 5 个种子）在同一世界参数下，B 价格候选减流对照的钳制 RMSE 在 120 步为 −1.770 tick [−1.990, −1.525]，在 200 步变为 +0.813 tick [+0.608, +1.014]。训练步数因此应与数据和候选一起登记。

## Step 4.1b　B 题收敛网格与纯 GRU 对照

登记五个种子 `103, 137, 211, 293, 367`，每点共用 32 个开发日、每模拟日 6 个窗口和增强世界 `info_drift=1.80, informed_frac=0.25`。校准命名空间为 `p0-step41b-calibration-v1`。同一对照的两个模型共用模拟日、初始种子和逐日 rollout 随机输入。下表所有差值均为候选减 `x11`。RMSE 单位为 tick，NLL 单位为 nats/event；改善数为钳制 RMSE 差小于零的种子数。95% 区间使用同一组 2,000 次日抽样跨候选、父模和重复配对，训练种子范围另报。

Grid A 的 `x12` 使用 `own_start=inside` 的 `self` 标记。Grid B 只把模型训练的标记资格限制到非知情母单，价格主干、`own_start` 条件和独立背景权重仍相同。两类标签可改变随机数消耗及后续训练窗口。每个步数运行各自的 OneCycleLR 计划，表格比较独立拟合的方案。

B 的纯 GRU 菜单使用同根训练日和种子另训两层匿名 GRU `x02`。开发运行以独立训练清单和权重引用登记该背景。流侧 `x13` 保持父模型价格权重；联合 `b_joint` 保持 `x12` 的自身标记价格权重。清单的单层 GRU 价格与替代的两层匿名 GRU 均在冻结实现上完成拟合。试跑已核对替代权重的主干、标记状态和层数。

| 自由末点响应（tick） | A、B | 0.75 | [−0.25, +0.25] | — |
| 钳制末点响应（tick） | A、B | 0.75 | [−0.25, +0.25] | — |
| 下一事件 NLL（nats/event） | A、B | 0.03 | [−0.02, +0.02] | 护栏 `max_delta = +0.06` |

按 `assess_candidate()` 对五种子合并区间判定。单项门控要求区间上端不高于 `max_delta`，区间整体高于阈值判为 `REFUTED`，跨越阈值判为 `INCONCLUSIVE`。等效要求整个合并区间落在等效带内。单种子极值及改善数用于描述训练重复。64 个正式测试日目前只登记计划数，正式复验留待 Step 4.2 启动。

### 复现定稿校准

在 Stochopia 根目录执行，OpenHyra 保持相邻目录。命令拟合两套模拟 train/dev、写入候选与诊断的逐日读数，并将七项配对效应及判定写入各自的 `summary.json`。拟合记录保存在各命名空间的 `DevelopmentStore`，后续 `Entry` 须使用该拟合存储或导入对应的 `FitRecord`。替代背景 `x02` 的层数仅在其单独拟合时生效。

```bash
env PYTHONPATH=.:../OpenHyra .venv/bin/python - <<'PY'
from pathlib import Path
import torch
from stochopia.common import atomic_write_json
from tasks.stochopia_tier0 import calibrate

torch.set_num_threads(1)
for namespace in ('p0-step41b-calibration-v1', 'p0-step41b-replication-v1'):
    manifest = calibrate.build_manifest(namespace=namespace)
    output = Path('outputs/phase4-step41c/reproduced') / namespace
    output.mkdir(parents=True, exist_ok=False)
    direct, measured, diagnostic_pairs = calibrate._measure(manifest, output)
    summaries = {}
    for scene in manifest.scenarios:
        sid = scene.scenario_id
        summaries[sid] = calibrate._calibrate_case(
            scene, manifest.analysis, direct[sid], measured[sid], diagnostic_pairs[sid],
            tuple(manifest.train_seeds), manifest.splits['dev'].unit_ids, manifest.analysis[0].n_resamples,
        )
    atomic_write_json(output / 'summary.json', summaries)
PY
```
